# Lingua-AI — Концепт и архитектура

## 1. Проблема и инсайт

Существующие обучалки (Duolingo, Babbel) учат всех одинаково. Живой репетитор адаптируется, но дорог и не помнит каждого ученика идеально. **AI может то, чего не может ни один из них: бесконечно терпеливо вести персональную методику и помнить про каждого юзера всё.**

Преимущество продукта = **движок памяти про ученика**, а не контент.

## 2. Пользовательский путь (v1)

1. Онбординг (язык — русский, цель, мотивация).
2. **Диагностика уровня** — адаптивный тест ~15–20 вопросов → CEFR + слабые темы.
3. Первые уроки на слабых темах, каждая тема подаётся в нескольких концепциях.
4. Система выявляет рабочую концепцию → дальше учит преимущественно ей.
5. Spaced repetition закрепляет пройденное.
6. Аудирование вплетено в уроки. Speaking — отдельный модуль (поэтапно).

## 3. Архитектура (4 блока)

### Блок A. Диагностика (Placement Engine)
- Адаптивный тест: правильный ответ → сложнее, ошибка → проще.
- Покрывает: грамматику, лексику, чтение, аудирование (минимально).
- Выход: CEFR-уровень + вектор слабых тем с весами.

### Блок B. Профиль ученика (Learner Model) — ЯДРО
Структура записи на юзера:
```
user_profile {
  cefr_level: A1..C2
  skills: { grammar, vocab, listening, reading, speaking }  // 0..100
  weak_topics: [{ topic, weight, last_seen, mastery }]
  preferred_concept: rule-first | examples-first | context-story | contrast-native
  concept_scores: { rule-first: {acc, retention, n}, ... }  // накопленный сигнал
  srs_queue: [{ item, due_date, ease, interval }]           // spaced repetition
}
```

### Блок C. Движок концепций (Pedagogy Engine)
- Концепции: `rule-first`, `examples-first`, `context-story`, `contrast-native`.
- Новая тема → подаётся в 2–3 концепциях.
- Замер по каждой: `accuracy` (моментальный %) + `retention_d1` (через день).
- Score = взвешенная сумма (retention важнее accuracy).
- Закрепление концепции: только после 3–5 сессий накопления (анти-шум).
- Periodic exploration: иногда (ε-greedy) пробуем не-лучшую концепцию — вдруг юзер вырос.

### Блок D. Закрепление (SRS Engine)
- Алгоритм типа SM-2 (Anki) на уровне айтемов (слова, правила, паттерны).
- Тема считается «закрытой» при mastery ≥ порог И стабильном retention.
- Только тогда Pedagogy Engine открывает следующую тему.

## 4. Speaking & Listening (риск-блоки)

- **Listening:** Gemini TTS озвучивает → юзер выбирает/печатает что услышал. Дёшево, в v1.
- **Speaking:** юзер говорит → STT (Whisper) распознаёт → оценка фонетики/беглости. Дорого, хрупко. Прототипировать ОТДЕЛЬНО до интеграции. Не блокирует MVP-запуск.

## 5. Метрики продукта

- **Северная звезда:** доля юзеров, доведённых до mastery хотя бы по 1 теме за неделю.
- **Retention D1/D7** — выживаемость (главная боль обучалок).
- **Стоимость сессии** (токены LLM + TTS/STT) — считать перед запуском.

## 6. Что НЕ делаем в v1 (анти-раздутие)

- Полноценный speaking с оценкой акцента → v2 (прототип отдельно).
- Мультиязычный UI → только русский на старте.
- Соцфичи, лидерборды → позже.
